# IDP-11: Backstage Deployment Design

**Linear Issue:** [IDP-11](https://linear.app/idp-riza/issue/IDP-11/deploy-backstage-with-catalog-kubernetes-and-argocd-integration-for)
**Created:** 2026-04-08

## Overview

Deploy Backstage as the portal layer for the homelab platform with:
- Software catalog integrated with Crossplane-provisioned apps
- Kubernetes plugin for viewing workloads cluster-wide
- ArgoCD plugin for viewing deployment status

**Scope:**
- Deploy Backstage in-cluster via GitOps
- Auto-discover catalog entities from Crossplane apps
- Integrate Kubernetes and ArgoCD plugins
- Keep first rollout focused on visibility (no ingress, internal-only)

**Out of Scope:**
- Ingress/external access (future iteration)
- Scaffolder templates (future iteration)
- Advanced RBAC/customization

## Architecture

Backstage is deployed as a platform component under `platform/backstage/` with PostgreSQL persistence.

### Deployment Location

- **Type:** Platform component
- **Path:** `platform/backstage/`
- **Bootstrap:** `clusters/homelab/bootstrap/backstage-application.yaml`
- **Namespace:** `backstage`

### Components

**Backstage Instance:**
- Helm chart: `backstage` from `https://backstage.github.io/charts`
- Replicas: 1 (can scale with PostgreSQL already in place)
- Image: `backstage:latest`
- Resource limits: 256Mi-512Mi memory, 100m CPU

**PostgreSQL Database:**
- Deployed as Bitnami PostgreSQL subchart dependency
- Persistence: 8Gi PVC
- Auth: Auto-generated credentials stored in Kubernetes Secret
- Internal connection: `backstage-postgresql.backstage.svc.cluster.local`

### GitOps Structure

```
platform/backstage/
  ├── values.yaml            # Helm values for Backstage chart
  └── app-config.yaml       # Backstage app configuration

clusters/homelab/bootstrap/
  └── backstage-application.yaml  # ArgoCD Application manifest
```

**ArgoCD Application Pattern:**
```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: backstage
  namespace: argocd
spec:
  project: default
  sources:
    - repoURL: https://backstage.github.io/charts
      chart: backstage
      targetRevision: <version>
      helm:
        releaseName: backstage
        valueFiles:
          - $values/platform/backstage/values.yaml
    - repoURL: https://github.com/RizaSatya/homelab.git
      targetRevision: main
      ref: values
  destination:
    server: https://kubernetes.default.svc
    namespace: backstage
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
```

## Catalog Integration

### Discovery Strategy

**Simple filter-by-structure approach:**
- Only Crossplane-provisioned apps have `catalog-info.yaml` files
- Non-Crossplane apps (`web-riza`, `garmin-scraper`, etc.) don't have catalog files
- Backstage discovers `apps/*/catalog-info.yaml`
- Result: catalog automatically shows only Crossplane apps

### Crossplane Composition Update

The Crossplane composition for webapps will generate `catalog-info.yaml`:

```
apps/<name>/
  ├── catalog-info.yaml    # Generated by Crossplane
  └── app/
      ├── webapp.yaml
      └── (other manifests)
```

**Catalog Entity Template:**
```yaml
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: <app-name>
  description: <app-description>
  annotations:
    backstage.io/techdocs-ref: dir:.
    github.com/project-slug: RizaSatya/homelab
spec:
  type: service
  lifecycle: production
  owner: <owner-reference>
  system: homelab
```

### App Configuration

```yaml
catalog:
  locations:
    - type: github-discovery
      target: https://github.com/RizaSatya/homelab
      rules:
        - pattern: apps/*/catalog-info.yaml
  
  rules:
    - allow: [Component, System, API, Resource, Location]
```

## Kubernetes Plugin Integration

### Configuration

- Plugin: `@backstage/plugin-kubernetes-backend`
- Access: Cluster-wide read permissions
- Connection: In-cluster via `kubernetes.default.svc`

### RBAC

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: backstage
  namespace: backstage
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: backstage-cluster-read
subjects:
  - kind: ServiceAccount
    name: backstage
    namespace: backstage
roleRef:
  kind: ClusterRole
  name: view
  apiGroup: rbac.authorization.k8s.io
```

### App Configuration

```yaml
kubernetes:
  serviceLocatorMethod:
    type: 'multiInstance'
  clusters:
    - name: homelab
      url: https://kubernetes.default.svc
      authProvider: 'serviceAccount'
      skipTLSVerify: true
```

### Component View

Each catalog entity will show:
- Pods, deployments, services in the component's namespace
- Resource usage and status
- Events and logs

## ArgoCD Plugin Integration

### Configuration

- Plugin: `@backstage/plugin-argo-cd`
- Access: Reuses cluster credentials (no separate ArgoCD token)
- Connection: `argocd-server.argocd.svc`

### App Configuration

```yaml
argocd:
  username: admin
  password: ${ARGOCD_ADMIN_PASSWORD}
  appName: backstage
  url: https://argocd-server.argocd.svc
  waitFor: 5s
```

### Component View

Each catalog entity will show:
- ArgoCD Application status
- Sync status and history
- Health checks
- Deployment timeline

## Networking

### Internal-Only Access

**No ingress in first rollout:**
- Accessible only via port-forward: `kubectl port-forward -n backstage svc/backstage 7007:7007`
- In-cluster services can reach: `http://backstage.backstage.svc.cluster.local:7007`

**Service Configuration:**
```yaml
service:
  type: ClusterIP
  port: 7007
```

### Future Ingress

When ready for external access, enable ingress with:
- Hostname: `backstage.homelab.rizaes.com`
- TLS: cert-manager with Let's Encrypt
- Ingress class: nginx (or your default)

## Security

### ServiceAccount

- Backstage runs with dedicated ServiceAccount `backstage`
- PostgreSQL uses chart-default ServiceAccount

### Credentials

**PostgreSQL:**
- Auto-generated by Bitnami subchart
- Stored in Secret `backstage-postgresql`
- No secrets in Git

**ArgoCD:**
- Uses admin credentials stored as Kubernetes Secret
- Secret mounted as environment variable in Backstage pod
- ArgoCD plugin authenticates to ArgoCD API using these credentials

**Backstage:**
- No external auth (internal-only)
- User authentication: deferred to future iteration

### RBAC Summary

| Principal | Access | Scope |
|-----------|--------|-------|
| Backstage SA | view (read-only) | Cluster-wide |
| PostgreSQL SA | None | Namespace-only |

### Network Policies

Future iteration: add NetworkPolicy to restrict Backstage pods to:
- Kubernetes API server
- ArgoCD service
- PostgreSQL service
- No external egress

## Implementation Dependencies

1. **ArgoCD** - Already running: `argocd` namespace
2. **Kubernetes API** - Cluster access already available
3. **Git repository** - `https://github.com/RizaSatya/homelab` (existing)
4. **Crossplane** - Needs composition update to generate `catalog-info.yaml`
5. **ArgoCD Admin Password** - Must retrieve and store as Secret for Backstage plugin

## Acceptance Criteria Mapping

✅ **Backstage is running in the cluster and managed by GitOps**
- Deployed via ArgoCD Application
- Running in `backstage` namespace
- Managed by GitOps under `platform/backstage/`

✅ **Onboarded apps can appear in the catalog with useful ownership metadata**

- Kubernetes plugin shows pods, deployments, services
- ArgoCD plugin shows sync status, health, history
- Both accessible from component pages

✅ **Setup is ready for future scaffolder template to target this repo**
- Catalog structure in place
- Git integration configured
- Component entities follow Backstage schema

## Success Metrics

- Backstage pod running and healthy in `backstage` namespace
- Catalog shows all Crossplane-provisioned apps
- Component pages display Kubernetes workloads
- Component pages display ArgoCD Application status
- PostgreSQL database running and persistent

## Rollout Plan

1. Create `platform/backstage/values.yaml` with Helm values
2. Create `platform/backstage/app-config.yaml` with Backstage config
3. Create `clusters/homelab/bootstrap/backstage-application.yaml`
4. Create ServiceAccount and ClusterRoleBinding manifests
5. Git push and let ArgoCD sync
6. Verify Backstage pod is running
7. Verify PostgreSQL is running
8. Port-forward and access Backstage UI
9. Verify catalog shows Crossplane apps
10. Verify Kubernetes plugin shows workloads
11. Verify ArgoCD plugin shows deployment status

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| PostgreSQL PVC fills up | Low | Medium | Set appropriate storage limits, enable monitoring |
| Backstage pod OOM | Medium | High | Set generous memory limits, monitor usage |
| ArgoCD API unavailable | Low | Medium | Add retry logic to plugin config |
| Catalog discovery fails | Medium | Medium | Verify git connectivity, check App config |
